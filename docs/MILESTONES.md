**Environment gotchas for future sessions** (learned this session):
- Firebase emulators need **Java 21** for the newer `firebase` (nvm node22 → v15) but only Java ≤16 is installed. Use the **homebrew `firebase` 12.4.4** (default node/PATH) + `JAVA_HOME=.../jdk-16...` for emulator work — that combo is verified working. Installing JDK 21 would let the newer CLI run.
- Firebase cloud CLI ops (projects/apps) were run under **nvm node 22.12** (`export PATH="$HOME/.nvm/versions/node/v22.12.0/bin:$PATH"`); the app itself builds on node 20.11.
- Node 20.11 is below SDK 57's preferred 20.19.4 (warnings only so far). Project is pinned to **24.15.0** via `.nvmrc` — run `nvm use` first.
- **iOS simulator runtime**: ✅ installed 2026-07-12 — iOS 26.3.1 (23D8133), iPhone 17 boots, app verified live in Expo Go. The first `xcodebuild -downloadPlatform iOS` download got **silently purged by macOS** from the system asset cache (leaving orphaned "Ready" records → "runtime profile not found" / ENOENT on boot). Durable fix used: `xcodebuild -downloadPlatform iOS -exportPath <dir>` then `xcrun simctl runtime add <dmg>` — installs into `/Library/Developer/CoreSimulator/Images/`, which macOS does not purge. If it ever breaks again: `xcrun simctl runtime list -v` and check the Image Path actually exists.
- **Emoji render as [?] tofu boxes on the iOS 26.3.1 simulator** — ✅ **fixed 2026-07-12 by installing the iOS 26.4.1 runtime**. Cause: a **known Apple bug in the iOS 26.2–26.3.1 simulator runtimes** — Apple Color Emoji fails to load (`AppleColorEmoji-160px.ttc` is present in the runtime image, but the sim won't serve it). It is **system-wide in the sim, not an app bug**: Mobile Safari showed the same tofu, and RN `<Text>` tofu'd with *every* font config (Nunito, no fontFamily, no styles). Physical devices are unaffected. Verified: same emoji render correctly in Safari **and** in the app's charm picker on 26.4.1. Refs: [Apple forums 817957](https://developer.apple.com/forums/thread/817957), [XcodesOrg/xcodes#468](https://github.com/XcodesOrg/xcodes/issues/468).
  - **Getting 26.4.1 was painful** — `xcodebuild -downloadPlatform iOS -buildVersion <ver>` answers *"not available for download"* for every version except the one matched to Xcode 26.3, with or without `-exportPath`. What worked: read the asset catalog Xcode itself uses — `/System/Library/AssetsV2/com_apple_MobileAsset_iOSSimulatorRuntime/…xml` (plistlib) → gives the CDN `.aar` URL **and its `ArchiveDecryptionKey`**. Then: `curl` the `.aar` (Apple throttles **one connection to ~0.5 MB/s** — download in parallel byte ranges, ~12 conns → ~5 MB/s), `aea decrypt -i x.aar -o payload -key-value base64:<key>`, un-`pbzx` the payload (xz frames), `aa extract` → `AssetData/Restore/*.dmg`, then `xcrun simctl runtime add <dmg>`.
  - Both runtimes are installed; **use an iOS 26.4 device** (`xcrun simctl list devices`). The buggy 26.3.1 runtime can be reclaimed with `xcrun simctl runtime delete <id>` (~7.8 GB).
- **"No development build (com.timelinegoal.app)… is installed"** from `expo start` = the CLI session is in **development-build mode**, not Expo Go. This project has no `expo-dev-client` dep, so `expo start` defaults to Expo Go; the mode flips only via the **`s` keypress** in the running CLI (easy to hit thinking "s = simulator") or `--dev-client`. Nothing is persisted — restart the server or press `s` again; `npx expo start --go` forces Go mode. Same trap caused the CLI to demand `android.package` on 2026-07-11. No dev build is needed until Rive (M3+). Also: Expo Go's first cold bundle (~160s, 3734 modules) can outlive its request timeout → red "Could not connect" screen; just Reload (⌘R) — second bundle is warm and fast.
- Android emulator (Pixel_3a_XL_API_33): `npm start` → press `a`. Android reaches the Firebase emulators via `10.0.2.2` (handled in `src/lib/firebase.ts`).
- **Expo Go "UnexpectedServerData: No returned query result" (500 on manifest)** = a **stale Expo CLI login** (a `duccuong0810` session with an expired token) made the dev server's authenticated API calls fail. Fix: `npx expo logout` (local Expo Go dev needs no Expo login). Diagnose by `curl -H "Expo-Platform: ios" -H "Accept: multipart/mixed,application/expo+json,application/json" http://localhost:8081/` — 500 vs 200. Only log back in (fresh creds) when doing EAS builds/updates.
